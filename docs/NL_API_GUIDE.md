# 국립중앙도서관 **소장자료 검색** OpenAPI 가이드

> Base URL: `https://www.nl.go.kr/NL/search/openApi/search.do` (GET, 응답 **JSON**/UTF-8)
>
> **이 문서의 거의 전부가 라이브 실측이다.** 2026-08-12 `scripts/probe_api.py` 로 실제 API 를
> 약 150회 호출해 확정했다. 검증 등급 — ✅ **실측** / 📄 문서 / ❓ 미검증

---

## 1. 요청

### 1-1. 파라미터 ✅

| 파라미터 | 값 | 설명 |
|---|---|---|
| `key` | (인증키) | **필수**. 평문 쿼리 — 토큰 발급·AES·공인IP 등록 없음 |
| `apiType` | `json` | 응답 형식 |
| `srchTarget` | `title` 등 | 검색 대상 필드 (§1-2) |
| `kwd` | `교육불평등` | 검색어. **큰따옴표로 감싸면 구문검색** (§1-4) |
| `category` | `도서` 등 | 자료구분 (§1-3) |
| `pageNum` | `1` | 페이지 번호(1부터) |
| `pageSize` | `500` | 페이지당 건수. **최대 500** (§1-5) |

```
https://www.nl.go.kr/NL/search/openApi/search.do
  ?key=<인증키>&apiType=json&srchTarget=title&kwd=교육불평등&category=도서&pageNum=1&pageSize=500
```

**User-Agent 주의** — 자매 프로젝트(KCI)에서 공공기관 방화벽이 UA 로 차단하는 사례를 실측했다.
본 클라이언트는 브라우저형 UA 를 보낸다.

### 1-2. `srchTarget` — 지원 여부 ✅

기준: `kwd=오욱환`(실존 저자) 과 `kwd=교육과학사`(실존 출판사)로 교차 확인.

| 값 | 동작 | 근거 (kwd=오욱환 / 교육과학사) |
|---|---|---|
| `title` | ✅ 제목 | 13 / — |
| `author` | ✅ 저자 | **36** / 22 |
| `publisher` | ✅ 발행자 | **0** / **5,973** |
| `keyword` | ✅ 키워드 | — / — (교육불평등 41 vs title 63) |
| `total`·`kwd` | ✅ 전 필드 | 36 / 6,095 |
| `isbn`·`classNo`·`callNo`·`subject`·`all`·**오타** | 🔴 **조용히 `total` 로 폴백** | 전부 36 |

> 🔴 **미지원 값은 오류를 내지 않는다.** 저자명을 ISBN 필드에서 찾게 한
> `srchTarget=isbn&kwd=오욱환` 이 0건이 아니라 **전 필드 검색과 똑같은 36건**을 냈다.
> ISBN 으로 찾았다고 믿으면 실제로는 전 필드 결과를 받는다 — 조용한 실패다.
> ISBN 조회는 `srchTarget=total` 에 ISBN 문자열을 넣는 편이 정직하다(실측 1건 정상 회수).

### 1-3. `category` — 자료구분 ✅

**서버가 유효 목록을 직접 알려준다.** 잘못된 값을 주면 오류 013 에 목록이 실려 온다.

```
[도서, 고문헌, 학위논문, 잡지/학술지, 신문, 기사, 멀티미디어,
 장애인자료, 외부연계자료, 웹사이트, 기타, 해외한국관련자료 or 해외기록물]
```

> ⚠️ 고급검색 UI 에는 **'전체' 탭이 있지만 API 는 '전체' 를 거부한다**(오류 013).
> 전체 검색은 `category` 를 **아예 빼고** 호출한다.

`kwd=교육불평등` 실측 분포 — **자료구분별 합이 생략 시 total 과 정확히 일치**한다.

| 자료구분 | total | | 자료구분 | total |
|---|---:|---|---|---:|
| 기사 | 234 | | 웹사이트 | 3 |
| 학위논문 | 66 | | 외부연계자료 | 3 |
| 도서 | 63 | | 고문헌·신문·장애인자료·해외기록물·기타 | 0 |
| 잡지/학술지 | 9 | | **합계** | **382** |
| 멀티미디어 | 4 | | (category 생략) | **382** ✅ |

→ `category` 분할은 **500건 상한을 우회하는 검증된 수단**이다(§3-3).

### 1-4. 🔴 검색 의미론 — 기본은 제목 부분일치가 **아니다** ✅

`srchTarget=title` 은 **토큰 분해 + 적합도 순 정렬**이다. `교육불평등` 은 `교육`·`불평등` 으로
쪼개져 둘 중 하나만 든 제목도 회수된다.

| 검색식 | total | 회수 | 제목에 검색어 포함 | **오탐률** |
|---|---:|---:|---:|---:|
| `kwd=교육불평등` | 63 | 63 | 30 | **52%** |
| `kwd="교육불평등"` (큰따옴표) | 28 | 28 | **28** | **0%** |

**큰따옴표 구문검색이 실제로 동작한다** — 클라이언트의 `exact=True` 가 이 처리를 한다.

> ⚠️ **위 표의 '오탐률'을 그대로 믿지 말 것.** 이것은 *제목에 검색어 문자열이 있는가* 를 잰
> 것이지 *주제가 무관한가* 를 잰 것이 아니다. 초판은 이 수치를 근거로 "정밀한 코퍼스가
> 필요하면 exact 를 쓰라"고 적었는데, **검증해 보니 반대였다** → §1-4-a.

#### 1-4-a. 🔴 `exact` 는 코퍼스 수집에 쓰면 안 된다 ✅ 실측

`exact=True` 가 실제로 무엇을 버리는지 6개 검색어로 확인했다(자료구분 도서).

| 검색어 | 기본 | exact | **재현율 손실** | 버려진 것 중 구성어 모두 포함 |
|---|---:|---:|---:|---:|
| 교육형평성 | 31 | **5** | **84%** | 85% |
| 교육소외 | 84 | 25 | 70% | 88% |
| 디지털격차 | 46 | 18 | 61% | 96% |
| 교육불평등 | 63 | 28 | 56% | 71% |
| 학력격차 | 58 | 33 | 43% | 68% |
| 교육격차 | 244 | 168 | 31% | 61% |
| **합계** | **526** | **277** | **47%** | **76%** |

**버려지는 것은 노이즈가 아니라 핵심 문헌이다.** `교육형평성` 이 버린 26건의 실제 표제:

```
학습자 중심 관점에서 본 교육의 형평성과 수월성 연구
초중등교육의 형평성과 효율성에 대한 일 연구
OECD 국제지표로 본 한국교육의 형평성 분석
교육의 수월성과 형평성 : 미국 교육개혁의 교훈
영어교육 투자의 형평성과 효율성
```

**원인**: 한국어 복합어는 실제 표제에서 조사·수식어로 갈라진다(`교육의 형평성`,
`초중등교육의 형평성과`). 구문검색은 토큰 **인접**을 요구하므로 이들이 전부 탈락한다.

**변형어로도 회복되지 않는다** — `["교육형평성","교육 형평성","교육의 형평성"]` 로 확장해도
12건에 그쳐, 기본 검색 31건에 한참 못 미친다.

**결론**: 기본값은 `False` 로 둔다. `exact` 의 용도는 **좁고 정확한 조회**다 —
전체 표제를 아는 특정 자료 찾기, 동명이의 구분, 상한에 걸린 검색어의 total 을 줄여
분할 수집을 돕는 보조 수단. 코퍼스 수집에는 기본 검색을 쓰고 걸러내기는 후처리로 한다.

**`kwd` 안에서 작동하지 않는 문법** ✅

| 시도 | 결과 |
|---|---|
| `kwd=교육 AND 불평등` 처럼 **kwd 안에 쓴** AND/OR/NOT | ✗ 연산자가 아니라 그냥 토큰. `kwd=AND` 단독 검색이 **451,670건** |
| `&&` | ✗ 무시(공백과 동일) |
| 작은따옴표 · `=검색어` · `^검색어` | ✗ 무시 |
| `matchType`·`exactYn`·`searchType`·`titleMatch` | ✗ 무시 |
| `srchTarget=title_exact`·`titleFront` 등 | ✗ 폴백(전 필드 검색) |

> 🔴 **정정(2026-08-12 재검증)** — 초판은 여기에 "`detailSearch=true&f1=&v1=&and1=` 무시" 와
> "필드 간 불리언 조합 불가" 를 적었으나 **둘 다 틀렸다.** §1-4-b 참조.
> 원인은 판정 논리였다: 초판 프로브는 *기준 질의와 total 이 같으면 무시된 것* 으로 봤는데,
> **f-슬롯은 `srchTarget`/`kwd` 와 등가라 같은 total 이 나오는 것이 오히려 동작한다는 증거**였다.
> 데이터를 정반대로 읽은 것이다.

### 1-4-b. ✅ 필드 간 불리언 — `detailSearch` + f-슬롯 (동작함)

```
detailSearch=true & f1=<필드> & v1=<값> [& and1=AND|OR|NOT & f2=<필드> & v2=<값>] …
```

**⚠️ `detailSearch=true` 가 없으면 f-슬롯은 오류다**(초판이 이걸 빼고 시험한 적도 있다).

**f-슬롯 ≡ `srchTarget`/`kwd`** — 실측으로 total 과 **첫 레코드까지 동일**:

| 질의 | total | 첫 표제 |
|---|---:|---|
| `srchTarget=publisher&kwd=교육과학사` | 5,973 | (교실을 바꿀 수 있는) 지리수업 설계 |
| `detailSearch=true&f1=publisher&v1=교육과학사` | **5,973** | **동일** |
| (대조) 검색어 없음 | 오류 | — |
| (대조) `srchTarget=title&kwd=교육과학사` | 5,875 | 다름 |

**`and1` 이 실제 불리언으로 동작한다** — `category=도서` 기준:

| 질의 | total |
|---|---:|
| 저자:오욱환 | 36 |
| 저자:오욱환 **AND** 제목:교육 | **27** |
| 저자:오욱환 **OR** 제목:교육 | 197,660 |
| 저자:오욱환 **NOT** 제목:교육 | **9** |
| (참고) 제목:교육 단독 | 197,651 |

> **검산이 맞는다**: `AND(27) + NOT(9) = 36 = 부모`. 우연이 아니라 **정확한 이분할**이다.
> OR 도 포함배제와 일치한다(36 + 197,651 − 27 = 197,660).
> 상한을 넘는 질의에서도 성립한다 — `교육복지`(1,856) 를 `학교`·`지역`·`정책`·`아동` 으로
> 각각 AND/NOT 분할했을 때 **4번 모두 합이 정확히 1,856**이었다.
> → **누락 없는 분할 축**이다(`licYn` 처럼 새지 않는다). §3-3 참조.

### 1-5. `pageSize` 상한은 500 ✅

| pageSize | 실제 반환 | 비고 |
|---:|---:|---|
| 100 | 100 | |
| 200 | 200 | |
| **500** | **500** | 한 번의 호출로 상한 전량 |

→ 500건 수집이 **5회 호출에서 1회로** 줄었다.

### 1-6. ✅ 정렬 — `sort` + `order` (동작함)

> 🔴 **정정(2026-08-12 재검증)** — 초판은 "`sort` 미지원, 전부 무시"라고 적었으나 **틀렸다.**
> 후보값을 `title_asc`·`pubyear_desc`·`PUBLISH_YEAR/DESC` 처럼 **지어내서** 시험했는데,
> 실제 값은 색인 필드명(`i` 접두)이었다. **값 몇 개를 못 맞힌 것을 기능 부재로 단정**한 것이다.

```
sort=<색인필드> & order=asc|desc
```

| `sort` 값 | 동작 | asc ≠ desc |
|---|---|---|
| `ipub_year` (발행년) | ✅ | ✅ asc → 1926년 자료가 최상위 |
| `ititle` (표제) | ✅ | ✅ |
| `iauthor` (저자) | ✅ | ✅ |
| `ipublisher` (발행자) | ✅ | ✅ |
| `iregdate` (등록일) | ✅ | ✅ |
| `ikdc`·`icall_no` | ✗ 무시 | — |
| `pub_year`·`title`·`regdate` (`i` 없는 이름) | ✗ 무시 | — |

**정렬 뒤집기가 500 상한 우회에 매우 효과적이다** — `교육복지`/`도서`(1,856건) 실측:

| 조합 | 누적 회수 | 요청 |
|---|---:|---:|
| 무정렬만 | 500 (27%) | 1 |
| + `ipub_year` asc/desc | **1,247 (67%)** | 3 |
| + `ititle` asc/desc | 1,558 (84%) | 5 |
| + `iauthor` asc/desc | **1,746 (94%)** | **7** |

> **`ipub_year` 의 asc 와 desc 는 교집합이 0건**이었다 — 완전히 다른 레코드를 준다.
> 참고: 현행 `auto_partition` 깊이 3은 7,028건 질의에 **60요청으로 67%** 인데,
> 정렬 뒤집기는 1,856건 질의를 **7요청으로 94%** 회수한다. 훨씬 싸고 정확하다.

### 1-6-b. ✅ 발행년 필터 — `ipub_year` (동작함, 단일 연도만)

> 🔴 **정정(2026-08-12 3차 재검증)** — 초판은 "서버측 연도 필터 부재"라고 적었고,
> 정정판에서도 "확인되지 않음"으로 남겨 뒀으나 **둘 다 틀렸다.** `sort` 와 **똑같이**
> 색인 필드명(`i` 접두)이었고, 초판이 시험한 11개 후보(`pubYear`·`year`·`startPubYear` …)에는
> 그 이름이 없었다. **같은 실수 패턴의 네 번째 재발이다.**

```
ipub_year=<4자리 연도>      # 단일 연도. 범위 지정은 되지 않는다
```

**실측 확인** (`교육복지`/`도서`, 전체 1,856건):

| 값 | total | 표본 발행년 |
|---|---:|---|
| `ipub_year=2020` | 62 | 2020 · 2020 · 2020 · 2020 · 2020 |
| `ipub_year=2019` | 55 | 전부 2019 |
| `ipub_year=2015` | 76 | 전부 2015 |
| `ipub_year=1990` | 1 | 1990 |

**분할 축으로서의 성질**

| 항목 | 값 |
|---|---|
| 1960~2026 합 | **1,772 / 1,856** (차이 −84, 약 4.5%) |
| **500 초과 연도** | **없음** — 연도 하나로 모든 셀이 상한 아래로 내려간다 |
| 누락 원인 | 발행년이 **빈 레코드**(실측 5.2%)는 어떤 연도로도 잡히지 않는다 — `licYn` 과 같은 유형 |
| 비용 | 연도 수만큼 요청(1960~2026 전수는 67회). 표본에서 **실존 연도만** 뽑으면 크게 준다 |

⚠️ **범위 지정은 안 된다** — `2019~2021`·`2019-2021`·`[2019 TO 2021]` 전부 0건.

⚠️ **f-슬롯에는 연도 필드가 없다.** `f2=발행년&v2=2020`(69) 과
`f2=ZZZ존재하지않는필드&v2=2020`(69) 이 **같은 값**이다 — 미지의 필드명은 무시되고
`교육복지 AND 2020` 토큰 검색이 될 뿐이다. 연도 필터로 오인하면 안 된다.

⏭️ **미구현** — 값 목록이 고정이 아니라 표본에서 뽑아야 해서 현행 `PARTITION_AXES`
(고정 값 집합) 구조와 결이 다르다.

## 2. 응답

### 2-1. 봉투 ✅

최상위 **7개 키**.

```json
{"total":63,"kwd":"교육불평등","pageNum":1,"pageSize":2,"category":"도서","sort":"","result":[ … ]}
```

> 🔴 **검색 결과가 0건이면 `result` 키가 아예 없다.**
> `{"total":0,"kwd":…,"pageNum":…,"pageSize":…,"category":…,"sort":""}`
> 이것은 오류가 아니라 정상적인 '결과 없음'이다.
> ⚠️ 반대로 `total > 0` 인데 `result` 가 없으면 **레코드 누락**이므로 오류로 취급해야 한다
> (빈 목록으로 통과시키면 조용한 절단이 된다).

### 2-2. 하이라이트 마크업 ✅

매칭된 **토큰마다** `<span class="searching_txt">` 가 붙고, `titleInfo` 뿐 아니라
`pubInfo` 등 다른 필드에도 실린다.

```json
"titleInfo": "<span class=\"searching_txt\">교육</span> <span class=\"searching_txt\">불평등</span> : 학교<span class=\"searching_txt\">교육</span>에 의한 …",
"pubInfo":   "<span class=\"searching_txt\">교육</span>과학사"
```

파서가 전 필드에서 제거하되 원본은 `raw` 에 보존한다.
⚠️ 태그를 지우면 토큰 사이 공백이 남는다 — 원제가 `교육 불평등` 이면 결과도 `교육 불평등` 이지
`교육불평등` 이 아니다. 제목 비교 시 공백 정규화가 필요하다.

## 3. 🔴 500건 상한

### 3-1. 사실 ✅

- 오류코드 `012 DATA LIMIT 500`
- 실측: `교육복지` total **1,856** → 실제 회수 **500건**
- **기준은 레코드 오프셋이다**(페이지 수가 아니다):

| pageSize | 끊긴 지점 | 누적 회수 |
|---:|---|---:|
| 10 | page **51** 에서 빈 응답 | **500** |
| 100 | page **6** 에서 빈 응답 | **500** |

→ `pageSize` 를 어떻게 잡아도 501번째에 닿지 못한다. 클라이언트는 레코드 수 기준으로 막는다.

### 3-2. 페이지네이션으로 해결되는가 — **안 된다** ✅

상한이 오프셋에 걸려 있어 같은 검색식으로는 도달할 수 없다.

### 3-3. 전수 수집 방법 — 검색 공간 분할

#### 사용할 수 있는 **서버측 축** ✅ (2026-08-12 전수 탐색)

응답 필드명을 그대로 파라미터로 넘겨보는 방식으로 찾았다. **대부분은 무시되고 셋만 동작한다.**

| 파라미터 | 동작 | 성질 |
|---|---|---|
| `category` | ✅ | **완전분할** — 값별 total 의 합 = 전체 |
| `manageName` | ✅ | **완전분할** — 본관 974 + 디지털도서관 872 + 어린이청소년 10 = 1,856 = 전체 |
| `licYn` | ✅ | ⚠️ **손실 있음** — 값이 **빈 레코드**가 존재해 어떤 값으로도 못 잡는다 |
| `kdcName1s` | ✅ | 동작하나 한 값(사회과학 1,674/1,856)에 쏠려 분할 효과 낮음 |
| `kdcCode1s`·`classNo`·`typeCode`·`typeName`·`menuName`·`mediaName`·`placeInfo`·`docYn`·`isbn`·`controlNo`·`regDate`·`lang`·`detailSearch`·`f1` … | ✗ | 전부 무시 |

> ⚠️ **이름만 보고 대칭을 가정하면 안 된다** — `kdcCode1s`(코드)는 무시되는데
> `kdcName1s`(이름)는 동작하고, `licYn` 은 되는데 `docYn` 은 안 된다.
>
> `licYn` 의 손실은 실측으로 확인했다: 교육복지/도서/본관 974건에 대해 licYn 을 **A~Z 전수**
> 탐색했으나 D·F·L·N·S 다섯 값 합계가 472건에 그쳤다. 나머지 502건은 licYn 이 비어 있다.

#### 재귀 분할 — `auto_partition=True`

상한에 걸린 조각만 다음 축으로 더 쪼갠다. **핵심은 부모 조각도 상한까지 받아 합집합에 넣는 것**이다
— 그러면 `licYn` 처럼 불완전한 축을 써도 손해가 나지 않는다(합집합은 항상 부모 이상).

`교육복지` 전체 7,028건 기준 **실측**:

| 깊이 | 축 | 회수 | 비율 | 요청 |
|---:|---|---:|---:|---:|
| — | 분할 없음 | 500 | 7% | 1 |
| 1 | `category` | 2,134 | 30% | 13 |
| 2 | `+manageName` (기본값) | 3,265 | 46% | 25 |
| 3 | `+licYn` | **4,722** | **67%** | 60 |

#### 그 밖의 수단

| 방법 | 효과 | 등급 |
|---|---|---|
| **검색어 세분화** | 조각마다 500 한도를 새로 받는다. `nl_collect(terms=[…])` | ✅ |
| **`exact=True` 구문검색** | total 자체가 줄어든다. ⚠️ 재현율 손실이 크다(§1-4-a) | ✅ |
| ~~연도 범위 분할~~ | ✗ 서버측 연도 필터 부재(11개 후보 무시). ⚠️ 단 값 이름을 못 맞혔을 수 있음 | ✅ 부재 확인 |

#### ✅ 정렬 뒤집기 (`sort_depth`) — **구현 완료**, 가장 값싼 수단

분할 축과 **직교한다**: 저쪽은 검색 공간을 값으로 쪼개고, 이쪽은 **같은 조각을 다른 순서로
다시 긁는다.** `asc` 와 `desc` 의 교집합이 0건이라 정렬축 하나가 상한을 사실상 2배로 늘린다.

**`교육복지` / `도서`(1,856건) 라이브 실측 — 🎉 전수 수집 달성**

| 설정 | 회수 | 비율 | 요청 |
|---|---:|---:|---:|
| 우회 없음 | 500 | 27% | 1 |
| `sort_depth=1` | 1,247 | 67% | 3 |
| `sort_depth=3` | 1,746 | 94% | 7 |
| `auto_partition` 깊이2 | 1,600 | 86% | 18 |
| **`auto_partition`2 + `sort_depth`1** | **1,854** | **100%** | 24 |
| **`auto_partition`3 + `sort_depth`2** | **1,856** | **100%** | 28 |

> 🎉 **이 문서는 오랫동안 "전수 수집은 불가능하다"고 적어 왔으나, 두 수단을 함께 쓰면
> 100% 회수된다.** 정렬 뒤집기만으로도 7요청에 94% 라 비용 대비 효과가 압도적이다.
> ⚠️ 상한에 걸리지 않은 검색식은 훑지 않는다(호출 낭비 없음).

#### ⚠️ f-슬롯 AND/NOT 이분할 (`bisect_depth`) — 구현했으나 **보통 열등하다**

`AND + NOT = 부모` 가 모든 깊이에서 정확하다(4분할 20+143+188+1505 = **1,856**, 깊이3도 검산 통과).
슬롯은 **좌결합·순차 적용**이고 3개 이상 이어붙일 수 있다. `licYn` 처럼 새지 않는
**유일한 무제한 정확 분할 축**이다.

분할어는 받은 레코드 제목에서 후보를 뽑되 **실제 AND 건수를 1건짜리 요청으로 미리 재서**
절반에 가까운 것을 고른다(표본 빈도만 보면 쏠려서 68%에 정체했다).

**그런데 실측하면 진다.** `교육`/`도서`(197,651건):

| 방식 | 회수 | 요청 |
|---|---:|---:|
| 정렬만 `sort_depth=5` | 5,321 | 11 |
| **분할3 + 정렬1** | **17,893** | **60** |
| 이분할8 + 정렬1 | 11,633 | **135** |

**회수는 적고 요청은 2배**다. 분할어 크기를 재느라 요청을 쓰는데, 대형 코퍼스에서는
제목 토큰이 고르게 갈리지 않아 그 비용을 회수하지 못한다.

→ **기본 비활성**(`bisect_depth=0`). 쓸 자리는 **다른 축을 모두 소진했을 때** —
`category`·`manageName`·`licYn` 를 전부 고정한 조각이 여전히 500을 넘는 경우다.

**자료구분 분할 실측** — 합이 정확히 일치하므로 겹치지 않는 완전 분할이다.

| 검색어 | category 생략 total | 자료구분별 합 | 분할 안 함 | **분할** | 배수 |
|---|---:|---:|---:|---:|---:|
| 교육불평등 | 382 | 382 ✅ | 382 | 382 | 1.0× |
| 교육복지 | 7,028 | 7,028 ✅ | 500 | **2,134** | 4.3× |
| 교육 | 784,809 | 784,809 ✅ | 500 | **4,559** | 9.1× |

⚠️ **전수는 아니다.** 개별 자료구분도 500을 넘을 수 있다(교육복지: 기사 3,879 · 도서 1,856 ·
학위논문 659). `meta.axes[].partition` 의 `capped_categories`·`unreachable` 이 남은 손실을
보고한다(교육복지의 경우 4,894건 도달 불가).
호출 수는 자료구분 수만큼 는다(실측 1회 → 13회).

**`exact=True` 의 total 축소 실측**

| 검색식 | 기본 | exact |
|---|---:|---:|
| 교육복지 (category 생략) | 7,028 | 1,751 |
| 교육복지 (도서) | 1,856 | 635 |
| 교육불평등 (category 생략) | 382 | 134 |
| 교육불평등 (도서) | 63 | **28** |

→ 상한 아래로 내려가면 전수가 되지만, 그렇지 않을 수도 있다(교육복지는 여전히 초과).
두 기법은 함께 쓸 수 있다.

### 3-4. 하지 말아야 할 것

`nl_collect` 의 `year_from`/`year_to`·`contains` 는 **이미 받은 레코드에 대한 후처리**다.
서버가 500건만 줬다면 필터는 그 안에서만 작동한다 — **상한을 풀어주지 않는다.**

### 3-5. 코드가 알려주는 신호

| 필드 | 뜻 | 처방 |
|---|---|---|
| `truncated` | 이번 호출이 `total` 보다 적게 받았다 | 대개 `max_records` 를 올리면 해결 |
| `cap_hit` | `total` > 500 — **API 자체가 더 안 준다** | `max_records` 로는 불가. §3-3 |
| `fetched` / `returned` | 회수량 / 후처리 필터 후 반환량 | 둘의 차이는 절단이 아니라 필터 |
| `meta.cap_hit_terms` | 상한에 걸린 검색어 | 그 검색어만 쪼개면 된다 |

## 4. 오류 ✅

실측 원문(잘못된 인증키):

```json
{"errorCode":"011","errorMsg":"INVALID KEY:인증키값이 유효하지 않습니다."}
```

| 코드 | 메시지 | 등급 |
|---|---|---|
| `000` | SYSTEM ERROR | 📄 |
| `010` | NO KEY VALUE | 📄 |
| `011` | INVALID KEY:인증키값이 유효하지 않습니다. | ✅ |
| `012` | DATA LIMIT 500 | 📄 (§3 에서 동작은 실측) |
| `013` | CATEGORY ERROR:카테고리값을 확인하세요.[…목록…] | ✅ |
| `101` | SEARCH ERROR | 📄 |

> ⚠️ 파서는 이 표에 의존하지 않는다. `errorCode`/`errCode` 계열 키가 있고 **레코드가 없을 때만**
> 오류로 올린다. `resultCode` 는 **일부러 제외했다** — 국내 공공 API 는 이 키를 성공 표시로도
> 쓰는데(`"00"`), 오류로 해석하면 정상 응답을 통째로 버리게 된다(적대적 검증에서 재현됨).

판정은 **기준 호출의 `total` 과 비교**한다. ⚠️ 단, 검색어를 바꾸는 시도(`kwd=교육 AND 불평등`)는
total 이 달라져도 '해석됨'이 아니다 — 질의 자체가 달라진 것이므로 대조군이 필요하다.
