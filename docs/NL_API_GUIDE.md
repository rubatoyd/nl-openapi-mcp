# 국립중앙도서관 **소장자료 검색** OpenAPI 가이드

> Base URL: `https://www.nl.go.kr/NL/search/openApi/search.do` (GET, 응답 **JSON**/UTF-8)
>
> 이 문서의 **검증 등급**을 항상 함께 읽을 것:
> - ✅ **실측** — 실제 응답 1,124건(2026-08-11 수집) 또는 수집 로그로 확인
> - 📄 **문서** — 국립중앙도서관 공식 안내서 기재 사항(라이브 재확인 전)
> - ❓ **미검증** — 추정. 라이브 확인 전에는 코드가 의존하지 않는다
>
> ⚠️ 2026-08-12 현재 `www.nl.go.kr`(124.137.58.36) 이 개발 환경에서 **TCP 접속 자체가 불가**하다
> (443·80 모두 타임아웃, DNS 는 정상). 따라서 이번 판은 **기존 실응답 데이터로만** 확정했다.
> 접속이 복구되면 아래 ❓ 항목을 실측으로 승격할 것 — `docs/작업일지.md` 참조.

## 1. 요청

### 1-1. 검증된 파라미터 ✅

수집 스크립트가 이 조합으로 **1,124건을 실제 회수**했다(11개 검색어).

| 파라미터 | 값 예시 | 설명 |
|---|---|---|
| `key` | (인증키) | **필수**. 평문 쿼리 파라미터 — 토큰 발급·AES·공인IP 등록 없음 |
| `apiType` | `json` | 응답 형식 |
| `srchTarget` | `title` | 검색 대상 필드 |
| `kwd` | `교육불평등` | 검색어 |
| `category` | `도서` | 자료 유형 필터 |
| `pageNum` | `1` | 페이지 번호(1부터) |
| `pageSize` | `100` | 페이지당 건수 |

```
https://www.nl.go.kr/NL/search/openApi/search.do
  ?key=<인증키>&apiType=json&srchTarget=title&kwd=교육불평등&category=도서&pageNum=1&pageSize=100
```

### 1-2. 미검증 파라미터 ❓

`srchTarget` 의 다른 값(`total`·`author`·`publisher`·`isbn` 등), `sort`,
연도·KDC 필터의 서버측 지원 여부는 **확인되지 않았다**. 클라이언트는 `srch_target` 을
`title` 로 기본 지정하고 나머지는 통과만 시킨다(`**extra`) — 임의로 가정하지 않는다.

### 1-3. User-Agent 주의 📄✅

자매 프로젝트(KCI)에서 **공공기관 방화벽이 User-Agent 로 차단**하는 사례를 실측했다
(`curl` 기본 UA → HTTP 400, 브라우저 UA → 200). 수집 스크립트도 `Mozilla/5.0` 을 명시했고,
본 클라이언트도 브라우저형 UA 를 보낸다.

### 2-1. 봉투 ✅

```json
{ "total": 1856, "result": [ { …24개 필드… }, … ] }
```

- `total` — 검색식 전체 건수. **`result` 길이와 다를 수 있다**(§3 참조)

## 3. ⚠️ 500건 상한 — 이 API 의 핵심 제약

### 3-1. 사실

- ✅ **실측이 1차 근거다**: 검색어 `교육복지` 의 `total` 은 **1,856**인데 실제 회수는
  **500건**에서 멈췄다. 수집 스크립트는 30페이지(=3,000건)까지 허용했고 종료 조건도
  `total` 도달이었으나, **6페이지째부터 빈 배열**이 돌아와 멈췄다.
- 📄 **문서가 그 원인을 설명한다**: 오류코드 `012 DATA LIMIT 500 — 페이지 조회 500건 초과 제한`.
  ⚠️ 단, 이 표는 **서지정보(SEOJI) API 안내서**(`SEOJI_OPENAPI_GUIDE_v1.0.doc`)에 실린 것이고
  소장자료 검색용 안내서에서 직접 확인한 것이 아니다. 두 API 가 같은 오류 체계를 쓴다는
  보장은 없다 — 다만 관측된 500 이라는 수치가 정확히 일치하므로 같은 제약으로 본다.
- ❓ **상한의 기준이 오프셋인지 페이지 수인지는 미확정**이다. 관측은 `pageSize=100` 한 조건뿐이라
  "500 레코드"와 "5 페이지"를 구별할 수 없다. 클라이언트는 **레코드 수 기준**으로 막아
  (`page * pageSize >= 500` 이면 중단) 어느 쪽이든 안전하게 동작한다.
  `pageSize=10` 으로 50건에서 끊기는지 확인하면 판별된다 — 접속 복구 후 실측할 것.

```
교육불평등: total=63    수집=63
교육격차:   total=244   수집=244
…
교육복지:   total=1856  수집=500  ⚠절단
```

### 3-2. 페이지네이션으로 해결되는가 — **안 된다**

같은 검색식 안에서는 `pageNum` 을 아무리 올려도 501번째 레코드에 도달할 수 없다.
`pageSize` 를 키워도, 페이지를 나눠도 마찬가지다 — 상한은 **오프셋**에 걸려 있다.

### 3-3. 그러면 전수 수집은 어떻게 하는가 — **검색식을 쪼갠다**

절단은 페이징이 아니라 **검색 공간 분할**로 푼다. 각 조각의 `total` 이 500 미만이 되게 만든다.

| 방법 | 효과 | 검증 등급 |
|---|---|---|
| **검색어 세분화** — 넓은 어휘 1개 → 좁은 어휘 여러 개의 합집합 | 조각마다 500 한도를 새로 받는다. `nl_collect(terms=[…])` 가 이 전략이다 | ✅ (합집합 로직 실측) |
| **`category` 분할** — 자료 유형별로 나눠 조회 | 서버측 필터라 조각별 `total` 이 실제로 줄어든다 | ✅ (파라미터 동작 실측) |
| **`sort` 뒤집기** — 오름차순 500 + 내림차순 500 | 최대 1,000건까지 확보(여전히 전수는 아님). KCI 에서 같은 우회책을 씀 | ❓ (`sort` 지원 미검증) |
| **연도·KDC 서버측 필터** | 가장 깔끔하나 **파라미터 지원 여부 미확인** | ❓ |

### 3-4. 하지 말아야 할 것 — 로컬 필터로 착각하기

`nl_collect` 의 `year_from`/`year_to`·`contains` 는 **이미 받은 레코드에 대한 후처리**다.
서버가 500건만 줬다면 필터는 그 500건 안에서만 작동한다 — **상한을 풀어주지 않는다.**
(회귀 테스트 `test_연도필터는_로컬후처리라_상한을_풀어주지_않는다` 가 이 성질을 고정한다.)

### 3-5. 코드가 알려주는 신호

| 필드 | 뜻 | 처방 |
|---|---|---|
| `truncated` | 이번 호출이 `total` 보다 적게 받았다 | 대개 `max_records` 를 올리면 해결 |
| `cap_hit` | `total` > 500 — **API 자체가 더 안 준다** | `max_records` 로는 해결 불가. §3-3 대로 분할 |
| `meta.cap_hit_terms` | 상한에 걸린 검색어 목록 | 그 검색어만 쪼개면 된다 |
| `meta.union_upper_bound` | 축별 `total` 합(합집합 상한) | 실제 합집합은 이 값 이하 |

## 4. 오류코드 📄❓

> ⚠️ 출처는 **서지정보(SEOJI) API 안내서**다. 소장자료 검색 API 가 같은 코드 체계를 쓰는지는
> 미확인 — `012` 만 실측 수치(500)와 일치해 간접 확인됐다. 파서는 이 표에 의존하지 않고,
> 어떤 코드가 오든 `ParseError` 로 올린 뒤 표에 있으면 설명을 덧붙일 뿐이다.

| 코드 | 메시지 | 뜻 |
|---|---|---|
| `000` | SYSTEM ERROR | 서버 내부 오류 |
| `010` | NO KEY VALUE | 인증키 누락 |
| `011` | INVALID KEY | 유효하지 않은 인증키 |
| `012` | DATA LIMIT 500 | 500건 초과 조회 제한 (§3) |
| `101` | SEARCH ERROR | 검색 조건 또는 검색 서버 오류 |

> ❓ 오류 응답의 **키 철자**(`errorCode`/`errCode`/…)는 미검증이다. 파서는 후보를 넓게 보고,
> 어느 것이든 잡히면 `ParseError` 로 올린다. `result` 키 자체가 없으면 그것도 오류로 취급한다
> — 빈 목록으로 조용히 통과시키면 **인증키 오류가 '검색결과 0건'으로 둔갑**하기 때문이다.

## 5. 서비스 구분 (혼동 주의)

국립중앙도서관은 **별개의 API 를 여러 개** 운영한다. 호스트와 경로가 다르다.

| 서비스 | 엔드포인트 | 본 패키지 |
|---|---|---|
| **소장자료 검색** | `www.nl.go.kr/NL/search/openApi/search.do` | ✅ **이것** |
| 서지정보(SEOJI) | `librarian.nl.go.kr/LI/search/openApi/seojiSearch.do` | v0.1.0 까지 사용, v0.2.0 에서 교체 |
| 정보나루 | `data4library.kr` | 별개 서비스 — 다루지 않음 |

v0.1.0 은 서지정보 API 를 썼으나 **최신 소장본이 검색되지 않아** v0.2.0 에서 소장자료 검색으로
교체했다. 두 API 는 응답 스키마가 완전히 다르다(서지정보의 `seojiYear`·`pageInfo` 등은 여기 없다).
