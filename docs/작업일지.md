## 2026-08-12 (2) — v0.2.0: 대상 API 교체(서지정보 → 소장자료 검색) · 기동 불능 3종 수정

### 배경
"국립중앙도서관 소장자료 검색 MCP 를 **새로 만든다**"로 착수했으나, 점검 결과
`coding project/NL openAPI/` 에 **이미 프로젝트가 존재**했다(2026-07-30, v0.1.0 릴리스,
`rubatoyd/nl-openapi-mcp` public). 다만 대상 API 가 달랐다 — **서지정보**(`seojiSearch.do`).
사용자 판단: *"서지정보는 최신 소장본이 검색이 안된다"* → **소장자료 검색으로 교체**, 기존 레포 재사용.

### 응답 스키마 확정 — 추정 없이
`투고논문/교육불평등 지도/4_데이터/국립중앙도서관_단행본/` 에 **실응답 1,124건**(11개 검색어)과
그것을 만든 수집 스크립트 `c2.py`·로그 `c2_log.txt` 가 남아 있었다. 여기서 전부 확정했다.

- **호출 규격** — `key`·`apiType=json`·`srchTarget=title`·`kwd`·`category=도서`·`pageNum`·`pageSize`
- **봉투** — `{"total": …, "result": [ … ]}`
- **24개 필드** — 전건에 키가 존재하되 값이 빌 수 있음(결측률 전수 집계 → 가이드 §2)

### 실측이 아니었으면 틀렸을 것 3가지
1. **`docYn`·`licYn` 은 불리언이 아니다.** 이름이 `…Yn` 이라 Y/N 으로 읽히지만 실제는 열거코드
   (`NL_VIEWER`·`LD_VIEWER`·`FILE`·`LINK`·`N` / `L`·`F`·`S`·`D`·`N`·`Y`).
   실측 1,124건에 `docYn="Y"` 는 **한 건도 없다** — `== "Y"` 로 판정했으면 전건 오판이었다.
   (KCI 의 `pubi-year`·`isseue` 오타 사례와 같은 종류의 함정이다.)
2. **`pubYearInfo` 형식이 하나가 아니다.** 4자리 703 · 6자리 186 · 8자리 168 · 9~14자리 8
   (`2019 (2020 9쇄)` 같은 값) · 빈값 59. 정수 변환이나 단순 앞 4자 절단은 조용히 깨진다.
3. **`controlNo` 는 31.0% 가 빈다.** 온라인자료(`typeCode=D1`)엔 KOLIS 제어번호가 없다.
   반면 `id` 는 **전건 존재** → 중복제거 1차 키는 `id` 여야 한다.

### 🔴 500건 상한 — 이 API 의 지배적 제약
- 공식 오류코드 **`012 DATA LIMIT 500`** (v0.1.0 이 남긴 서지정보 가이드에 기재돼 있었다)
- 실측 확증: `c2_log.txt` 의 `교육복지: total=1856 수집=500 ⚠절단`.
  수집 스크립트는 30페이지(3,000건)까지 허용했으나 6페이지째부터 빈 배열이 왔다.

**질문: 페이지네이션으로 해결되는가 → 안 된다.** 상한이 오프셋에 걸려 있어 같은 검색식으로는
501번째에 도달할 수 없다. `pageSize` 를 키우거나 페이지를 나눠도 동일하다.

**해결은 검색 공간 분할이다** — 각 조각의 `total` 이 500 미만이 되게 만든다.
검색어 세분화(✅ `nl_collect(terms=[…])`) · `category` 분할(✅) ·
`sort` 뒤집기(❓ 미검증) · 연도/KDC 서버측 필터(❓ 파라미터 지원 미확인).

⚠️ **함정**: `year_from`/`contains` 는 **로컬 후처리**라 상한을 풀어주지 않는다.
회귀 테스트 `test_연도필터는_로컬후처리라_상한을_풀어주지_않는다` 로 이 성질을 고정했다.

### ⚠️ 라이브 검증 불가 — 접속 차단
`www.nl.go.kr`(124.137.58.36) 이 **TCP 443·80 모두 타임아웃**이다. DNS 는 정상 해석된다.

| 호스트 | IP | 결과 |
|---|---|---|
| www.nl.go.kr | 124.137.58.36 | **FAIL** TimeoutError 10.06s |
| librarian.nl.go.kr | 124.137.58.36 | **FAIL** TimeoutError 10.01s |
| open.kci.go.kr | 203.252.27.235 | OK 0.04s |
| pypi.org / www.google.com | — | OK 0.03~0.04s |

샌드박스 문제가 아니다 — `dangerouslyDisableSandbox` 로도, PowerShell `Test-NetConnection` 으로도
동일하게 실패했다(`PingSucceeded: False`). 2026-08-11 에 같은 호스트로 20초 read timeout 이
기록된 것과 이어지는 증상이나, 같은 날 21:54 에 `c2.py` 는 1,124건을 정상 수집했다
→ **상시 차단이 아니라 시간대·경로에 따른 것**으로 보인다. 교육망 차단인지 서버측인지 미확정.

따라서 이번 판은 **기존 실응답으로만** 확정했고, 문서에 검증 등급(✅ 실측 / 📄 문서 / ❓ 미검증)을
필드·파라미터마다 표기했다. 코드는 ❓ 항목에 의존하지 않는다.
